# Phase 1.4 — Unify the Content ETL (scope)

> Spec: `2026-05-28-content-silo-bridge-design.md`. Parent plan: `2026-05-28-unified-data-build-plan.md` (this is the "big one, to scope").
> Builds on Phase 1.1 (canonical id scheme in `apps/data-import/server/src/lib/id-mapping.ts` — `canonicalContentId`, provenance, `validateContentIds`; 99.99% reference resolution on live data).
> Principle: **additive first, validate against real data (match rates/counts), then cut over.** Brain node ids never change. No GW content committed.

---

## Goal

One content pipeline that produces **canonical content docs (R2)** + the **`content_entity` index**, consumed by both `game-data-store` (a projection) and `brain` (knowledge layer on top), with a **`content_node_link` crosswalk** bridging brain node ids ↔ canonical ids. Collapse the two ETLs, kill the drift, preserve brain graph integrity.

---

## Current state (verified)

- **data-import** (Cloudflare Worker): Wahapedia CSV + BSData XML → `id-mapping` (BSData-canonical datasheet ids; Phase 1.1 canonical ids for ability/stratagem/enhancement) → `data/*.json` in R2 → browser `game-data-store` (IndexedDB). Entry: `apps/data-import/server/src/lib/sync.ts`.
- **brain/build-graph** (`apps/brain/server/src/build-graph.ts`, ~1100 lines): reads a **separate static copy** of the Wahapedia JSON at `apps/data-import/client/public/wahapedia/`, plus GW markdown + community + Chapter Approved → ~25k `Node` docs (`apps/brain/server/src/lib/model.ts`) → R2 BRAIN bucket, partitioned by layer/faction (`lib/sync.ts`), refs separate, manifest, **Vectorize index keyed on node id**.
- **The silo:** the same content is produced twice; brain's static copy can drift from the live import.
- **Already aligned:** brain datasheet node `id` == `datasheetId` == BSData GUID == canonical datasheet id (`lib/parsers/game-data.ts:437`). Datasheet crosswalk is **identity**.
- **Tables exist** (`schema.ts`, migration `0001`, prod): `content_entity` (id/type/name/faction_id→self/parent_id→self/dataslate_id/r2_key) and `content_node_link` (brain_node_id PK / canonical_id FK / match_method ∈ {datasheet_id, name_faction, manual} / confidence). `scoring_mission`, `game_state`, `mission_game_state` already FK `content_entity`.
- **content_node_link today:** written **only** by `scripts/11th-ingest/build-brain-nodes.mjs` (manual, 11th cards/abilities; `match_method='manual'`), **not** wired into the main brain build.

## Target

```
            Wahapedia CSV + BSData XML
                      │
            one content producer (extend data-import worker — has both sources in memory)
                      ├─► R2 canonical docs  content/{type}/{id}.json   (source of truth + public surface)
                      └─► content_entity index rows (id/type/name/faction_id/parent_id/r2_key/dataslate_id)
                      │
   ┌──────────────────┴───────────────────┐
   ▼                                       ▼
game-data-store import = projection     brain/build-graph = consumes canonical docs for content payload;
of the canonical docs                   KEEPS its node ids; writes content_node_link (matched);
(IndexedDB, unchanged keys)             adds only the knowledge layer (rules/refs/community/errata)
```

## Steps (ordered — each additive + validated before the next consumer cuts over)

1. **Canonical content-doc producer** (in data-import server). Reuse `buildIdMapping` + `canonicalContentId`. Emit per-entity docs `content/{type}/{id}.json` to R2 for datasheet / weapon / faction / subfaction / detachment / ability / stratagem / enhancement (mission when a source exists). Granularity = brain's record pattern (parent + children aggregated at read). **Gate:** doc count == entity count per type; spot-check sample docs against source.

2. **`content_entity` population.** From the producer, idempotent upsert one row per entity: `id`=canonical, `type`, `name`, `faction_id`→content_entity, `parent_id`→content_entity (weapon→datasheet, detachment→faction), `r2_key`, `dataslate_id`. **Gate:** row counts == entity counts per type; FK integrity (no dangling faction_id/parent_id); re-run is a no-op (no dupes/changes).

3. **`content_node_link` crosswalk builder** (run during brain build; idempotent + reversible). For each brain content node:
   - **datasheet:** node id == canonical id → `match_method='datasheet_id'`, confidence 1.0 (identity — already aligned).
   - **weapon:** node's `datasheetId` + slug → `weapon:{datasheetId}:{slug}` → `datasheet_id`.
   - **ability / stratagem / enhancement:** match by name + faction to the canonical entity → `name_faction`; low-confidence flagged for review.
   - Park unmatched. **Brain node ids never change** (spec Decision 3). Fold the standalone `build-brain-nodes.mjs` manual links into this builder.
   - **Gate:** match rate counted (matched/unmatched/low-confidence), BCP-style; unmatched list produced; dropping the table leaves the graph untouched (reversible).

4. **Repoint brain build-graph to the canonical docs.** Replace the static `client/public/wahapedia/` read with the canonical content docs (one source). Brain stops re-deriving datasheet/weapon stats from its own copy; keeps node ids + scheme; bridges via crosswalk. **Gate:** brain build output diff = content payload identical-or-improved, **node ids unchanged**, manifest unchanged except content, no ref breakage, Vectorize not re-keyed.

5. **Repoint game-data-store import to the canonical docs** (projection). Either browser pulls canonical docs, or the producer keeps emitting `data/*.json` sourced from the canonical layer (zero client change). **Gate:** IndexedDB store keys/shape identical; consumer apps (versus, list-builder) unaffected (1.1 fields already additive).

6. **Retire the duplicate derivation** once 4 + 5 are validated: remove brain's standalone Wahapedia copy/derivation. One content pipeline + a brain knowledge layer remain.

---

## Blast radius / risks

- **Two LIVE pipelines + deployed workers.** Brain **Vectorize index is keyed on node id** → node ids MUST NOT change (crosswalk only, never re-key).
- The static brain copy at `apps/data-import/client/public/wahapedia/` may already be **stale** vs live R2 — reconcile before cutover (diff first).
- **Additive-first:** produce canonical docs + `content_entity` + crosswalk *alongside* existing outputs; validate match rates; only then cut consumers over and retire the old path. Every step reversible.

## Open questions to settle before coding

1. Brain content nodes: stay **crosswalk-bridged** (spec Decision 3 — safe, no Vectorize rebuild) vs eventually **adopt canonical ids** (cleaner, but blast radius). → Recommend crosswalk-only now; revisit later.
2. Producer location: **extend the data-import worker** (already holds both sources + does the mapping) vs a new service. → Recommend extend data-import.
3. Missions: still a stub here; 11th-ingest already builds `scoring_mission` + manual `content_node_link`. Fold its mission/card links into the unified crosswalk (step 3) vs keep separate. → Fold in.
