# Phase 2 — List Data Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote the list-builder's data model from a flat IndexedDB + denormalized-text backup to a fully relational schema (`list`, `list_unit`, `list_unit_loadout`, `list_unit_loadout_weapon`) with FK ties into `content_entity`, proper points-derivation logic, attachment constraints, and updated tRPC routers — while keeping the IndexedDB hot-path client experience intact.

**Architecture:** The new relational tables replace the old `lists`/`list_units` tables as the server-of-truth. The client retains IndexedDB as the hot-path for fast UX and offline; every write to IndexedDB fires a background sync to the server. The server now stores the full configured-unit shape (loadouts, attachments, points snapshot, dataslate reference) instead of the old flat/denormalized backup. Consumer apps (Versus, Game Tracker, Tournament) will FK `list_unit.id` from the server side. A pure-TypeScript points-derivation engine lives in `packages/db/src/list-points.ts` and is shared by both server router and client-side preview.

**Tech Stack:** TypeScript, Drizzle ORM (libSQL/SQLite), tRPC + Zod, Vitest (unit + integration), Playwright (e2e), Turso (prod), in-memory libSQL (tests).

---

## Architecture Decision: Server-of-Truth (not mirror)

The old design was "IndexedDB primary, server backup (fire-and-forget)." Phase 2 promotes the server to **truth** for the relational list shape because:

1. Other apps need to FK `list_unit.id` — that requires stable server-side rows.
2. Points derivation against a versioned dataslate must be auditable; a pure-client snapshot cannot be re-validated on demand.
3. The new tables carry richer data (loadouts, attachment roles, dataslate snapshot) that the old `list_units` table didn't support.

**What stays the same:** IndexedDB continues to be used by the client for browsing, fast unit-card lookups, and UX responsiveness. But CRUD for `list` and `list_unit` rows is server-first: every mutation calls tRPC first, then updates IndexedDB. The restore flow (`list.getAll`) remains available.

## Task 3: Points-derivation engine (TDD)

**Files:**

The engine is a pure-TS module with no DB calls. It receives pre-loaded cost data and computes points. This makes it testable without a DB and usable both server-side (in the router) and client-side (imported into the browser).

### Types

```typescript
// The cost layer (dataslate-versioned, loaded from content_entity / R2)
export interface UnitCostRecord {
  datasheetId: string
  dataslateId: string
  modelCount: number
  points: number
}

export interface WargearOptionRecord {
  datasheetId: string
  dataslateId: string
  weaponId: string
  points: number
}

export interface EnhancementRecord {
  id: string
  points: number
}

// An in-memory loadout (mirrors list_unit_loadout + list_unit_loadout_weapon)
export interface InMemoryLoadout {
  modelCount: number
  weapons: Array<{ weaponId: string; count: number }>
}

// Inputs to deriveListUnitPoints
export interface PointsDerivationInput {
  datasheetId: string
  dataslateId: string
  loadouts: InMemoryLoadout[]
  enhancementId?: string
  unitCosts: UnitCostRecord[]    // all costs for this datasheet + dataslate
  wargearOptions: WargearOptionRecord[] // all wargear costs for this datasheet + dataslate
  enhancements: EnhancementRecord[]
}
```

### Functions

```typescript
/**
 * Derive points for a single list_unit.
 *
 * Formula: unit_cost(datasheet, total_models) + Σ(loadout wargear costs) + enhancement.points
 *
 * unit_cost: pick the UnitCostRecord where modelCount = Σ(loadout.modelCount).
 * If no exact match, pick the largest modelCount <= totalModels (band costing).
 * wargear: for each weapon in each loadout, find matching WargearOptionRecord and add
 *   points * weapon.count.
 * enhancement: add enhancement.points if enhancementId is set.
 *
 * Returns 0 if no matching unit cost (graceful degradation when cost data missing).
 */
export function deriveListUnitPoints(input: PointsDerivationInput): number

/**
 * Derive total_points for a list as Σ deriveListUnitPoints across all units.
 */
export function deriveListTotalPoints(unitInputs: PointsDerivationInput[]): number
```

```typescript
export interface UnitCostRecord {
  datasheetId: string; dataslateId: string; modelCount: number; points: number
}
export interface WargearOptionRecord {
  datasheetId: string; dataslateId: string; weaponId: string; points: number
}
export interface EnhancementRecord { id: string; points: number }
export interface InMemoryLoadout {
  modelCount: number; weapons: Array<{ weaponId: string; count: number }>
}
export interface PointsDerivationInput {
  datasheetId: string; dataslateId: string; loadouts: InMemoryLoadout[]
  enhancementId?: string; unitCosts: UnitCostRecord[]
  wargearOptions: WargearOptionRecord[]; enhancements: EnhancementRecord[]
}

export function deriveListUnitPoints(input: PointsDerivationInput): number {
  const { datasheetId, dataslateId, loadouts, enhancementId,
          unitCosts, wargearOptions, enhancements } = input

  const totalModels = loadouts.reduce((sum, l) => sum + l.modelCount, 0)

  // Band costing: find largest record where modelCount <= totalModels
  const relevantCosts = unitCosts
    .filter(c => c.datasheetId === datasheetId && c.dataslateId === dataslateId
                 && c.modelCount <= totalModels)
    .sort((a, b) => b.modelCount - a.modelCount)

  const baseCost = relevantCosts[0]?.points ?? 0
  if (relevantCosts.length === 0) return 0

  // Wargear: per weapon per model in the loadout
  let wargearCost = 0
  for (const loadout of loadouts) {
    for (const weapon of loadout.weapons) {
      const option = wargearOptions.find(
        w => w.datasheetId === datasheetId && w.dataslateId === dataslateId
             && w.weaponId === weapon.weaponId
      )
      if (option) {
        wargearCost += option.points * weapon.count * loadout.modelCount
      }
    }
  }

  // Enhancement
  const enhancementCost = enhancementId
    ? (enhancements.find(e => e.id === enhancementId)?.points ?? 0)
    : 0

  return baseCost + wargearCost + enhancementCost
}

export function deriveListTotalPoints(unitInputs: PointsDerivationInput[]): number {
  return unitInputs.reduce((sum, u) => sum + deriveListUnitPoints(u), 0)
}
```

```typescript
export interface CanLeadRecord {
  leaderDatasheetId: string; bodyguardDatasheetId: string; role: 'leader' | 'support'
}
export interface ExistingAttachment {
  characterUnitId: string; attachRole: 'leader' | 'support'
}
export interface AttachmentValidationInput {
  characterUnitId: string; characterDatasheetId: string
  bodyguardUnitId: string; bodyguardDatasheetId: string
  proposedRole: 'leader' | 'support'
  existingAttachments: ExistingAttachment[]
  canLeadRecords: CanLeadRecord[]
}
export type AttachmentResult = { valid: true } | { valid: false; reason: string }

export function validateAttachment(input: AttachmentValidationInput): AttachmentResult {
  const { characterUnitId, characterDatasheetId, bodyguardUnitId,
          bodyguardDatasheetId, proposedRole, existingAttachments, canLeadRecords } = input

  if (characterUnitId === bodyguardUnitId) {
    return { valid: false, reason: 'Self-attachment is not allowed' }
  }

  const allowed = canLeadRecords.find(
    r => r.leaderDatasheetId === characterDatasheetId
      && r.bodyguardDatasheetId === bodyguardDatasheetId
      && r.role === proposedRole
  )
  if (!allowed) {
    return { valid: false, reason: `Cannot lead: ${characterDatasheetId} cannot ${proposedRole} ${bodyguardDatasheetId}` }
  }

  const slotTaken = existingAttachments.some(a => a.attachRole === proposedRole)
  if (slotTaken) {
    return { valid: false, reason: `${proposedRole.charAt(0).toUpperCase()}${proposedRole.slice(1)} slot already filled for this unit` }
  }

  return { valid: true }
}

import { z } from 'zod'

const battleSizeEnum = z.enum(['Combat Patrol', 'Incursion', 'Strike Force', 'Onslaught', 'unknown'])

const loadoutWeaponSchema = z.object({
  weaponId: z.string().optional(),
  count: z.number().int().min(1).default(1),

export const listV2Router = router({
  create: protectedProcedure
    .input(z.object({
      name: z.string().min(1),
      edition: z.enum(['10th', '11th']).default('11th'),
      battleSize: battleSizeEnum.default('unknown'),
      author: z.string().optional(),
      factionId: z.string().optional(),
      subfactionId: z.string().optional(),
      detachmentId: z.string().optional(),
      dataslateId: z.string().optional(),
      source: z.string().default('list-builder'),
    }))
    .mutation(async ({ ctx, input }) => {
      const id = generateId()
      const now = Date.now()
      await ctx.db.insert(list).values({
        id, userId: ctx.user.id, name: input.name, edition: input.edition,
        battleSize: input.battleSize, totalPoints: 0, source: input.source,

        subfactionId: input.subfactionId ?? null, detachmentId: input.detachmentId ?? null,

      name: z.string().min(1).optional(),
      edition: z.enum(['10th', '11th']).optional(),
      battleSize: battleSizeEnum.optional(),
      author: z.string().optional(),
      factionId: z.string().nullable().optional(),
      subfactionId: z.string().nullable().optional(),
      detachmentId: z.string().nullable().optional(),
      dataslateId: z.string().nullable().optional(),
      totalPoints: z.number().int().min(0).optional(),
    }))
    .mutation(async ({ ctx, input }) => {
      const existing = await ctx.db.select().from(list)
        .where(and(eq(list.id, input.id), eq(list.userId, ctx.user.id)))
      if (!existing.length) throw new TRPCError({ code: 'NOT_FOUND' })
      const { id, ...fields } = input
      await ctx.db.update(list).set({ ...fields, updatedAt: Date.now() })
        .where(eq(list.id, id))
      return { success: true }
    }),

    .input(z.object({ id: z.string() }))

        .where(and(eq(list.id, input.id), eq(list.userId, ctx.user.id)))

              weapons: weapons.filter(w => w.loadoutId === lo.id),

        })),
      }
    }),

    .input(z.object({ id: z.string() }))
    .mutation(async ({ ctx, input }) => {
      await ctx.db.delete(list)
        .where(and(eq(list.id, input.id), eq(list.userId, ctx.user.id)))

    .input(z.object({
      listId: z.string(),

        .where(and(eq(list.id, input.listId), eq(list.userId, ctx.user.id)))
      if (!parentList.length) throw new TRPCError({ code: 'FORBIDDEN' })

      const id = generateId()
      await ctx.db.insert(listUnit).values({
        id, listId: input.listId,
        datasheetId: input.datasheetId ?? null,
        enhancementId: input.enhancementId ?? null,
        isWarlord: input.isWarlord ? 1 : 0,
        points: input.points,
        attachedToUnitId: input.attachedToUnitId ?? null,
        attachRole: input.attachRole ?? null,
      })
      return { id }
    }),

  updateUnit: protectedProcedure
    .input(z.object({
      id: z.string(),
      datasheetId: z.string().nullable().optional(),
      enhancementId: z.string().nullable().optional(),
      isWarlord: z.boolean().optional(),
      points: z.number().int().min(0).optional(),
      attachedToUnitId: z.string().nullable().optional(),
      attachRole: z.enum(['leader', 'support']).nullable().optional(),
    }))
    .mutation(async ({ ctx, input }) => {
      // Verify via list ownership
      const unit = await ctx.db.select().from(listUnit).where(eq(listUnit.id, input.id))
      if (!unit.length) throw new TRPCError({ code: 'NOT_FOUND' })
      const parentList = await ctx.db.select().from(list)
        .where(and(eq(list.id, unit[0]!.listId), eq(list.userId, ctx.user.id)))
      if (!parentList.length) throw new TRPCError({ code: 'FORBIDDEN' })

      // Attachment constraint: if setting an attachment, enforce ≤1 leader + ≤1 support per bodyguard.
      // NOTE: can_lead content ref validation (which character CAN lead which unit) requires
      // the cost layer from Phase 1.4. For Phase 2 we enforce the slot constraint only.
      if (input.attachedToUnitId && input.attachRole) {
        const siblings = await ctx.db.select().from(listUnit)
          .where(eq(listUnit.attachedToUnitId, input.attachedToUnitId))
        const slotTaken = siblings.some(
          s => s.id !== input.id && s.attachRole === input.attachRole
        )
        if (slotTaken) {
          throw new TRPCError({
            code: 'BAD_REQUEST',
            message: `${input.attachRole} slot already filled for this unit`,
          })
        }
      }

      const { id, isWarlord, ...rest } = input
      await ctx.db.update(listUnit).set({
        ...rest,
        ...(isWarlord !== undefined ? { isWarlord: isWarlord ? 1 : 0 } : {}),
      }).where(eq(listUnit.id, id))
      return { success: true }
    }),

  removeUnit: protectedProcedure
    .input(z.object({ id: z.string() }))
    .mutation(async ({ ctx, input }) => {
      const unit = await ctx.db.select().from(listUnit).where(eq(listUnit.id, input.id))
      if (!unit.length) return { success: true }
      const parentList = await ctx.db.select().from(list)
        .where(and(eq(list.id, unit[0]!.listId), eq(list.userId, ctx.user.id)))
      if (!parentList.length) throw new TRPCError({ code: 'FORBIDDEN' })
      await ctx.db.delete(listUnit).where(eq(listUnit.id, input.id))
      return { success: true }
    }),

  setLoadout: protectedProcedure
    .input(z.object({
      unitId: z.string(),
      loadouts: z.array(loadoutSchema),
    }))
    .mutation(async ({ ctx, input }) => {
      const unit = await ctx.db.select().from(listUnit).where(eq(listUnit.id, input.unitId))
      if (!unit.length) throw new TRPCError({ code: 'NOT_FOUND' })
      const parentList = await ctx.db.select().from(list)
        .where(and(eq(list.id, unit[0]!.listId), eq(list.userId, ctx.user.id)))
      if (!parentList.length) throw new TRPCError({ code: 'FORBIDDEN' })

      // Replace all loadouts for this unit
      await ctx.db.delete(listUnitLoadout).where(eq(listUnitLoadout.listUnitId, input.unitId))

      for (const loadout of input.loadouts) {
        const loadoutId = generateId()
        await ctx.db.insert(listUnitLoadout).values({
          id: loadoutId, listUnitId: input.unitId, modelCount: loadout.modelCount,
        })
        for (const weapon of loadout.weapons) {
          await ctx.db.insert(listUnitLoadoutWeapon).values({
            id: generateId(), loadoutId,
            weaponId: weapon.weaponId ?? null, count: weapon.count,
          })
        }
      }
      return { success: true }
    }),

  computePoints: protectedProcedure
    .input(z.object({ listId: z.string() }))
    .mutation(async ({ ctx, input }) => {
      // Verify ownership
      const parentList = await ctx.db.select().from(list)
        .where(and(eq(list.id, input.listId), eq(list.userId, ctx.user.id)))
      if (!parentList.length) throw new TRPCError({ code: 'NOT_FOUND' })
      // NOTE: full cost derivation (against content_entity cost layer) is a Phase 1.4 concern.
      // This procedure exists as the hook; it sums already-set .points snapshots.
      const units = await ctx.db.select().from(listUnit).where(eq(listUnit.listId, input.listId))
      const totalPoints = units.reduce((sum, u) => sum + u.points, 0)
      await ctx.db.update(list).set({ totalPoints, updatedAt: Date.now() })
        .where(eq(list.id, input.listId))
      return { totalPoints }
    }),
})
```

## Task 8: Validity recompute (editor vs read-only)

This is the spec's "editor validity" — recompute points against the saved dataslate snapshot, surface drift as red in the UI. The server-side hook is `listV2.computePoints`. The editor calls it after any unit/loadout change. Read-only consumers (Tournament, Versus) trust the saved `.points` and `.totalPoints` snapshots without recompute.

There is no `is_valid` column (per spec). The "validity" is derived at query-time by the editor comparing live-recomputed vs saved snapshot. This is a client-side concern for the editor UI, so no additional server changes are needed for Task 8.

**The key distinction** (must be encoded in tests):
- Editor: calls `computePoints` after changes → diff shown in red if `derivedPoints !== savedPoints`
- Read-only: trusts `list.totalPoints` as-is — no recompute
