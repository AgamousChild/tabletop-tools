Datacard Format Reference

The game-datacards.eu project (github.com/ronplanken/game-datacards) is an open-source React app that renders GW-format datacards from Wahapedia data — exactly what we need.

What game-datacards.eu provides

  • React components for unit cards, stratagem cards, enhancement cards, rule cards
  • GW-authentic layout — stat bars, weapon tables, ability boxes in official format
  • Faction SVG icons — every faction symbol as watermark on cards
  • Wahapedia data source — same data we already use
  • CSS variables for faction-specific color theming
  • Print-ready — designed for physical card printing

Proposal

Instead of designing our own card format from scratch, we adapt the game-datacards components into our brain UI. We already share the same data source (Wahapedia). Their components handle:

  • UnitCard (front/back/full) — the main datasheet
  • StratagemCard — stratagem display with CP diamond, phase, effect
  • EnhancementCard — enhancement with points cost and rules
  • RuleCard — detachment rules and army rules

What we ADD on top is the context overlay layer — the semi-transparent colored highlights that show which parts of the card are relevant to the current query, and the red arrow connectors between combo cards.

Two approaches:

A

Fork & Adapt game-datacards components

Take their UnitCard, StratagemCard, EnhancementCard React components. Strip the Ant Design dependency, restyle for our dark theme, add the context overlay layer. We own the code, can modify freely.

Pros

  • Proven GW-accurate layout
  • Full control
  • Components already React

Cons

  • Need to strip Ant Design
  • LESS → Tailwind conversion
  • Maintenance burden
B

Build our own using their layout as reference

Study the game-datacards layout structure and CSS, then build clean React + Tailwind components from scratch matching the GW format. Use their faction SVG icons. Designed for our dark theme from the start.

Pros

  • Clean codebase, no legacy
  • Tailwind-native, dark theme built in
  • Designed for our overlay feature

Cons

  • More work upfront
  • Must match GW format manually
  • Risk of deviating from authentic layout

Which approach? Or a mix?
